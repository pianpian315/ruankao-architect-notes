    一、计算机组成与体系结构¶

    1.1 数据表示（必考1题）¶

    原码、反码、补码、移码 - 正数：原码=反码=补码（最高位0） - 负数：反码=原码符号位不变其余取反；补码=反码+1 - 移码=补码符号位取反（用于浮点数阶码） - n 位补码表示范围：-2^(n-1) ~ 2^(n-1)-1（多一个负数）

    浮点数：阶码（移码）+ 尾数（原码/补码） - 规格化：尾数最高位非0 - 对阶：小阶向大阶看齐，尾数右移

    1.2 校验码¶

    校验码 检错 纠错 关键
    奇偶校验 1 位 不能 简单
    CRC 循环冗余 多位 不能 模2除法
    海明码 多位 1 位 2^k ≥ n+k+1

    海明码公式：信息位 n，校验位 k，需满足 2^k ≥ n+k+1（k 取最小满足值） - 8 位信息 → 至少 4 位校验位（2⁴=16 ≥ 8+4+1=13 ✓） - 16 位信息 → 至少 5 位校验位（2⁵=32 ≥ 16+5+1=22 ✓） - 32 位信息 → 至少 6 位校验位（2⁶=64 ≥ 32+6+1=39 ✓）

    1.3 流水线（高频）¶

    关键公式： - 流水线周期 = max(各段执行时间) - 执行 n 条指令耗时 = (k + n - 1) × Δt （k段流水线，Δt周期） - 加速比 = 顺序时间 / 流水线时间 - 吞吐率 TP = n / 总时间，最大吞吐率 = 1/Δt - 效率 = n×k×Δt / (k×总时间)

    1.4 存储系统¶

    二、操作系统（4-6题）¶

    2.1 进程管理（必考）¶

    进程三态/五态： - 三态：就绪 ⇄ 运行 → 阻塞 → 就绪 - 五态：增加新建、终止 - 注意：阻塞→运行 不存在；运行→就绪 是时间片用完

    线程 vs 进程： - 进程是资源分配单位，线程是 CPU 调度单位 - 同一进程的线程共享：代码段、数据段、打开的文件 - 线程独立的：栈、寄存器、程序计数器

    2.2 PV 操作（每年必考1-2题）¶

    P(S): S = S - 1; if S < 0 then 阻塞 V(S): S = S + 1; if S ≤ 0 then 唤醒

    经典模型套路： - 生产者-消费者：empty(初值=N缓冲区数)、full(初值=0)、mutex(=1) - 生产者：P(empty), P(mutex), 生产, V(mutex), V(full) - 消费者：P(full), P(mutex), 消费, V(mutex), V(empty) - 顺序应是 资源P → 互斥P → 临界区 → 互斥V → 资源V（顺序错会死锁）

    前趋图转 PV：每条弧对应一个信号量(初值0)，前节点 V，后节点 P

    2.3 死锁¶

    死锁四个必要条件（缺一不可）： 1. 互斥 2. 请求与保持（占有并等待） 3. 不可剥夺（不可抢占） 4. 循环等待（环路等待）

    死锁处理策略： - 预防：破坏4个条件之一 - 避免：银行家算法 - 检测：资源分配图化简 - 解除：资源剥夺、撤销进程、回滚

    最少资源数公式：n 个进程，每个需要 m 个同类资源，不发生死锁最少资源数 = n×(m-1)+1

    2.4 存储管理¶

    分页 vs 分段 vs 段页式： | 维度 | 分页 | 分段 | 段页式 | |------|------|------|--------| | 大小 | 固定 | 不固定 | 段不固定/页固定 | | 逻辑性 | 无 | 有 | 有 | | 共享 | 难 | 易 | 易 | | 碎片 | 内部碎片 | 外部碎片 | 内部碎片 |

    逻辑地址转换： - 分页：页号 × 页大小 + 页内偏移 - 注意页号转换为内存块号需查页表

    页面置换算法： - OPT(最优)：理想情况，无法实现 - FIFO：可能产生 Belady 异常（增加页框反而缺页增加） - LRU：最近最久未使用（栈/链表实现） - LFU：最少使用频率 - NUR/Clock：近似 LRU

    缺页率题套路： - 给定页面访问串和页框数，逐步模拟，标记缺页 - 缺页率 = 缺页次数 / 总访问次数

    工作集：进程在某段时间内访问的页面集合，用于防止抖动

    2.5 文件管理¶

    • 索引文件：直接索引、一级间接、二级间接、三级间接（题目常考最大文件大小计算）
    • 位示图：每位代表一个物理块（0空闲/1占用），第 i 个字第 j 位 → 块号 = i×字长 + j
    • 目录结构：单级、两级、树形（最常用）、图状（共享）

    2.6 设备管理与SPOOLing¶

    • SPOOLing（假脱机）：低速设备 → 高速磁盘 → 共享利用，使独占设备变为虚拟共享设备
    • 三大组成：输入井/输出井、输入/输出缓冲、输入/输出进程

    2.7 嵌入式 RTOS（实时操作系统）¶

    • 硬实时：必须在截止时间前完成（医疗、航天）
    • 软实时：偶尔超时可接受（视频流）
    • 调度算法：
    • RM（速率单调）：周期短优先级高（静态）
    • EDF（最早截止期优先）：动态，CPU利用率可达100%

    3.1 关系代数（必考）¶

    3.2 函数依赖与候选键（必考）¶

    函数依赖类型： - 完全依赖：X→Y 且 X 任何真子集都不能决定 Y - 部分依赖：X→Y 但 X 的某个真子集就能决定 Y - 传递依赖：X→Y, Y→Z, 则 X→Z 是传递依赖

    Armstrong 公理：自反、增广、传递；引申：合并、分解、伪传递

    候选键求解三步法： 1. 仅在依赖左侧出现的属性 → 必在候选键中 2. 未出现在任何依赖中的属性 → 必在候选键中 3. 仅在右侧出现的属性 → 必不在候选键 4. 以上属性求闭包 = 全集 → 即为候选键；否则补充中间属性

    3.3 范式（必考）¶

    范式 消除 判定
    1NF 非原子属性 字段不可再分
    2NF 非主属性对码的部分依赖 1NF + 无部分依赖
    3NF 非主属性对码的传递依赖 2NF + 无传递依赖
    BCNF 主属性对码的部分/传递依赖 所有依赖左部都含码
    4NF 多值依赖 -

    口诀："1非原子、2无部分、3无传递、BC左含码"

    模式分解： - 无损分解：分解后能还原原关系（必须保证） - 保持函数依赖：分解后所有原依赖仍成立 - 二元分解判定：R 分解为 R1, R2 是无损连接 ⟺ R1∩R2 → R1-R2 或 R1∩R2 → R2-R1

    3.4 SQL 与视图¶

    视图的优点： - 简化用户操作、增加安全性、提供逻辑独立性 - 但有更新限制（多表/聚合视图通常不可更新）

    索引：B+树索引、哈希索引、位图索引 - 适合建索引：经常查询、连接、排序的列 - 不适合：频繁更新、列基数小（如性别）

    触发器/存储过程：在数据库端执行，减少网络开销

    3.5 事务与并发控制¶

    ACID：原子性、一致性、隔离性、持久性

    事务隔离级别（隔离强度 低→高）： | 级别 | 脏读 | 不可重复读 | 幻读 | |------|------|-----------|------| | 读未提交 RU（最低） | √ | √ | √ | | 读已提交 RC | × | √ | √ | | 可重复读 RR | × | × | √ | | 可串行化 SE（最高） | × | × | × |

    注：MySQL InnoDB 默认 RR，Oracle/SQL Server 默认 RC。√ 表示可能出现该异常；× 表示已避免。

    封锁协议： - 一级：写前 X 锁，事务结束释放 → 防丢失修改 - 二级：一级 + 读前 S 锁，读完释放 → 防脏读 - 三级：二级 + S 锁事务结束才放 → 防不可重复读 - 两阶段封锁(2PL)：所有锁操作分成两个阶段(扩展期、收缩期)，可保证可串行化

    5.2 排序算法（必考）¶

    算法 平均 最坏 空间 稳定 特点
    冒泡 O(n²) O(n²) O(1) √ -
    简单选择 O(n²) O(n²) O(1) × 比较多交换少

    5.3 树与二叉树¶

    重要性质： - 二叉树第 i 层最多 2^(i-1) 个节点 - 深度为 k 的二叉树最多 2^k - 1 个 - 叶子数 n0 = 度2节点 n2 + 1 - 完全二叉树有 n 个节点，深度 = ⌊log₂n⌋ + 1

    遍历：先序(根左右)、中序(左根右)、后序(左右根) - 已知前序+中序，或中序+后序，可还原；前+后不可还原

    线索二叉树：把空指针指向前驱/后继

    B 树/B+ 树： - B 树：所有节点都存数据 - B+ 树：仅叶子存数据，叶子相连便于范围查询，数据库索引常用

    哈夫曼树： - 构造：每次取最小两个合并 - WPL = ∑(权值 × 路径长度)，无度为1节点 - 编码：左 0 右 1，前缀码

    AVL 树：左右子树高度差 ≤ 1，旋转：LL、RR、LR、RL

    📌 关于 MC/DC（修正条件/判定覆盖）：MC/DC 是 DO-178B（航空软件）和 ISO 26262（汽车功能安全）等行业标准的强制要求，覆盖强度介于"条件覆盖"与"条件组合覆盖"之间，但与条件组合覆盖维度不完全可比（MC/DC 要求每个条件独立影响判定结果，更聚焦"必要测试"而非"穷举"）。考试中如果出现 MC/DC 选项，记忆为"接近条件组合覆盖但更精简"即可。

    判定 vs 条件 vs 判定/条件 速记： - 判定（分支）覆盖：让每个判定的真假分支至少各执行一次 - 条件覆盖：让每个判定中每个原子条件的真假至少各取一次 - 判定/条件覆盖：同时满足判定覆盖 + 条件覆盖 - 条件组合覆盖：让每个判定中所有条件取值的组合至少各出现一次（2^n 种组合）

    黑盒方法：等价类、边界值、错误推测、因果图、判定表、正交试验

    测试阶段： - 单元测试：白盒为主，模块功能、接口、局部数据、边界、错误处理 - 集成测试：自顶向下（用桩）、自底向上（用驱动）、三明治 - 确认测试：α(开发场)、β(用户场) - 系统测试：恢复、安全、强度、性能、可用性、安装

    McCabe 环路复杂度 = 边数 - 节点数 + 2 = 判定节点数 + 1

    四种类型： - 改正性 Corrective（约 17-21%）：修 bug - 适应性 Adaptive（约 18-25%）：适应环境 - 完善性 Perfective（约 50-60%）：新需求 ★占比最大（Lientz & Swanson 数据 65%，国内教程多用 50%） - 预防性 Preventive（约 4%）：防患未然

    ⚠️ 易错点：考题问"软件维护中占比最大的是"——答完善性。 不同教材给出的具体百分比略有差异（清华版常用 50%，国际经典文献为 60-65%），但占比最大的是完善性这一结论是一致的。

    可维护性子特性：易分析性、易改变性、稳定性、易测试性、可移植性

    6.6 项目管理¶

    进度管理（PERT/CPM）： - 正向计算：最早开始、最早结束 - 反向计算：最晚开始、最晚结束 - 总时差 = LS - ES = LF - EF - 关键路径：总时差为 0 的路径，最长路径

    PERT 三点估算：期望 = (乐观 + 4×最可能 + 悲观) / 6 方差 = ((悲观 - 乐观)/6)²

    成本估算： - COCOMO：组织型/嵌入型/半独立型，三层（基本/中级/详细） - COCOMO II：应用组装、早期设计、后体系结构 - 功能点 FPA：与具体语言无关

    风险管理：识别 → 评估 → 规划 → 控制 - 风险敞口 RE = 概率 × 损失

    CMM/CMMI 等级（必考，注意 CMM 与 CMMI 命名不同）：

    等级 CMM（已淘汰，1991-2003） CMMI（现行，2002 至今） 核心特征
    L1 初始级 Initial 初始级 Initial 混乱、依赖个人英雄
    L2 可重复级 Repeatable 已管理级 Managed 基本项目管理流程
    L3 已定义级 Defined 已定义级 Defined 标准化、组织级过程
    L4 已管理级 Managed 量化管理级 Quantitatively Managed 量化目标 + 统计控制
    L5 优化级 Optimizing 优化级 Optimizing 持续过程改进

    ⚠️ 关键差异：CMM L2 叫"可重复级"，CMMI L2 才叫"已管理级"。考题中若题干用"CMM"则用旧名，用"CMMI"则用新名。目前考试以 CMMI 命名为主（CMM 已被 CMMI 取代），但选择题偶尔会用 CMM 旧名作干扰。

    7.1 架构风格（每年必考2-4题）¶

    五大类经典架构风格¶

    1. 数据流风格 - 批处理：以数据为驱动，每个组件依次处理（编译器早期） - 管道-过滤器：数据流式驱动，过滤器独立可并行可复用 - 优点：复用、并行、易扩展 - 缺点：交互式应用不适合、可能引入额外解析开销 - 例子：Unix 管道、编译器、信号处理

    2. 调用-返回风格 - 主程序-子程序：单线程、过程调用层级关系 - OO（面向对象）：封装、继承、多态 - 层次结构：每层只与相邻层交互，下层向上层提供服务 - 例子：OS、TCP/IP、ISO/OSI - 严格 vs 宽松层次（可跨层） - 客户/服务器(C/S)：胖客户端、二层架构 - 三层 C/S：表示层 + 业务逻辑层 + 数据层 - B/S：浏览器为统一客户端、瘦客户端

    3. 独立构件风格 - 进程通信：消息传递、RPC - 事件驱动/隐式调用：发布-订阅、组件松耦合 - 优点：复用、易演化 - 缺点：失去对计算的控制、数据交换困难

    4. 虚拟机风格 - 解释器：解释执行（脚本语言、规则引擎、JVM） - 4 部分：解释引擎、被解释代码、控制状态、当前状态 - 基于规则的系统：规则库 + 推理机 + 工作内存（专家系统）

    5. 仓库风格 - 数据库系统：传统数据库 - 黑板系统：知识源 + 黑板 + 控制（语音识别、AI、信号处理） - 超文本系统：Web

    现代架构风格¶

    6. SOA（面向服务） - 特征：松耦合、粗粒度、平台无关、有明确接口 - 通信：SOAP/REST，企业服务总线 ESB - 服务标准：WSDL（描述）、UDDI（注册发现）、SOAP（通信）、BPEL（编排）

    7. 微服务（与 SOA 对比常考） | 维度 | SOA | 微服务 | |------|-----|--------| | 通信 | ESB（智能管道） | 哑管道（HTTP/MQ） | | 数据 | 共享 | 独立数据库 | | 服务粒度 | 粗 | 细 | | 部署 | 集中 | 独立部署 | | 治理 | 集中 | 去中心化 |

    8. REST - 资源（URI）+ 表述（JSON/XML）+ 状态转移 - 6 大约束：客户端-服务器、无状态、可缓存、统一接口、分层系统、按需代码

    9. 闭环控制（过程控制）：传感器→控制器→执行器（嵌入式）

    十、分布式系统与中间件（3-5题）¶

    10.1 CAP 与 BASE（必考）¶

    CAP：一致性 + 可用性 + 分区容忍 → 三选二 - 网络分区不可避免，所以 P 必选 → 实际是 CP / AP 二选一 - CP（牺牲可用性保一致）：HBase、ZooKeeper、etcd、Consul（强一致模式） - AP（牺牲一致性保可用）：Eureka、Cassandra、CouchDB、DNS、Redis（默认主从异步复制）

    注：Redis 主从复制默认是异步，主节点宕机时可能丢数据，属于 AP；只有在 WAIT 命令或同步复制配置下才偏 CP。常见误区是把 Redis Sentinel 当成 CP，实际上 Sentinel 只是故障转移机制，不改变 Redis 的 AP 本质。

    BASE：基本可用、软状态、最终一致（互联网架构主流）

    10.2 分布式一致性¶

    Paxos / Raft：基于多数派的强一致协议 Gossip：最终一致，去中心化 Quorum (NWR)：N 副本数、W 写副本数、R 读副本数；W+R>N 强一致

    10.3 负载均衡算法¶

    • 轮询、加权轮询
    • 随机、加权随机
    • 最小连接数、最小响应时间
    • 一致性哈希（节点变化时影响小）
    • IP 哈希（同一用户落同一节点，会话粘滞）

    10.4 缓存策略¶

    • Cache Aside（旁路）：先读缓存，未命中读数据库；写时先更新数据库再删缓存
    • Read/Write Through：缓存与 DB 同步
    • Write Behind：异步写回 DB（性能高但有丢数据风险）

    类型 算法 密钥 速度 用途

    十二、系统可靠性（2-3题，必拿分）¶

    12.1 可用性公式¶

    可用性 A = MTBF / (MTBF + MTTR) = MTTF / (MTTF + MTTR)

    • MTBF（Mean Time Between Failures）：平均故障间隔（两次故障之间）
    • MTTF（Mean Time To Failure）：平均无故障时间（首次故障前）
    • MTTR（Mean Time To Repair）：平均修复时间

    💡 记忆：Between（间隔）→ MTBF；To Failure（到失效）→ MTTF；To Repair（到修好）→ MTTR。

    12.2 可靠性串并联¶

    串联：R = R1 × R2 × ... × Rn （任意一个坏全坏） 并联：R = 1 - (1-R1)(1-R2)...(1-Rn) （全坏才坏） 混联：先算并联块，再算串联

    12.3 容错技术¶

    • N 版本程序设计：多版本并行运行后表决
    • 恢复块：主块失败 → 验证测试 → 备份块
    • 防卫式程序设计：错误检测 + 损害评估 + 错误恢复
    • 冗余：硬件冗余、软件冗余、信息冗余、时间冗余

    12.4 系统性能评估¶

    性能指标： - 响应时间、吞吐量、资源利用率 - TPS（每秒事务）、QPS（每秒查询）

    评估方法： - 时钟频率法、指令执行速度法（MIPS、MFLOPS） - 等效指令法（吉布森混合法） - 综合理论性能法（CTP） - 基准程序法（最准）：SPEC、TPC

    【例 1】子网划分（必考 1 题）

    题干：某公司分配到 IP 地址 192.168.10.0/24，需要划分 5 个子网，每个子网至少容纳 25 台主机，请问： ①子网掩码应该是多少？②每个子网可用主机数？③第 3 个子网的网络地址和广播地址？

    解题步骤： 1. 算主机位：每子网 ≥ 25 台 → 主机位 m 满足 2^m - 2 ≥ 25 → m = 5（2^5-2=30 ≥ 25 ✓） 2. 算子网位：5 个子网 → 子网位 n 满足 2^n ≥ 5 → n = 3（2^3=8 ≥ 5 ✓） 3. 核验：n + m = 3 + 5 = 8 ✓（C 类主机位总 8 位） 4. 子网掩码：原 /24 + 借 3 位 = /27，即 255.255.255.224（224 = 11100000） 5. 块大小：256 - 224 = 32 6. 可用主机数：2^5 - 2 = 30 台 7. 子网列表： - 子网 1：192.168.10.0 / 27（广播 .31） - 子网 2：192.168.10.32 / 27（广播 .63） - 子网 3：192.168.10.64 / 27（广播 192.168.10.95） ← 答案 - 子网 4：.96 ～ .127 - 子网 5：.128 ～ .159

    速记口诀：先算主机位（满足容量）→ 再算子网位（满足数量）→ 块大小 = 256 - 末段掩码值

    【例 2】关键路径（CPM，必考 1 题）

    题干：项目活动表如下，求关键路径和工期：

    活动 紧前活动 工期(天)
    A - 5
    B - 7
    C A 6
    D A, B 8
    E C 4
    F D 3
    G E, F 5

    解题步骤： 1. 画前趋图（节点为活动）： 开始 → A → C → E ↘ ↓ G → 结束 D → F ↗ → B ↗ 2. 正向算最早开始 ES / 最早结束 EF（ES = 紧前活动 EF 的最大值，EF = ES + 工期）：

    活动 ES EF 计算
    A 0 5 -
    B 0 7 -
    C 5 11 ES = A的EF=5
    D 7 15 ES = max(A.EF=5, B.EF=7) = 7
    E 11 15 ES = C.EF=11
    F 15 18 ES = D.EF=15
    G 18 23 ES = max(E.EF=15, F.EF=18) = 18
    1. 工期 = G 的 EF = 23 天
    2. 逆向算 LS / LF，总时差 = LS - ES = 0 的活动构成关键路径
    3. 关键路径：B → D → F → G（7+8+3+5 = 23 ✓）

    易错点：当一个活动有多个紧前活动时，取 EF 最大值（不是平均）；关键路径可能有多条。

    【例 3】PERT 三点估算（必考 1 题）

    题干：某活动乐观工期 4 天、最可能 7 天、悲观 16 天。求期望工期和方差。

    公式： - 期望工期 E = (乐观 + 4 × 最可能 + 悲观) / 6 - 标准差 σ = (悲观 - 乐观) / 6 - 方差 σ² = ((悲观 - 乐观) / 6)²

    解： - E = (4 + 4×7 + 16) / 6 = (4 + 28 + 16) / 6 = 48 / 6 = 8 天 - σ = (16 - 4) / 6 = 2 - σ² = 4

    进阶：若问"该活动 95% 概率能在多少天内完成"，按正态分布： - 95% 置信区间 ≈ E + 1.645σ ≈ 8 + 1.645 × 2 ≈ 11.3 天

    【例 4】哈夫曼树 WPL（高频）

    题干：给定权值 {3, 5, 7, 9, 11}，构造哈夫曼树并求 WPL（带权路径长度）。

    解题步骤： 1. 每次取最小两个合并： - Step 1：取 3、5 → 合并节点 8。剩余 {7, 8, 9, 11} - Step 2：取 7、8 → 合并节点 15。剩余 {9, 11, 15} - Step 3：取 9、11 → 合并节点 20。剩余 {15, 20} - Step 4：取 15、20 → 合并节点 35（根）。完成。

    1. 画树并标层数（根为第 1 层，叶子层数 = 路径长度）： 35 / \ 15 20 / \ / \ 7 8 9 11 / \ 3 5

    2. WPL 计算（叶子权值 × 路径长度的累加）：

    3. 3 × 4 = 12
    4. 5 × 4 = 20
    5. 7 × 2 = 14
    6. 9 × 2 = 18
    7. 11 × 2 = 22
    8. WPL = 12 + 20 + 14 + 18 + 22 = 86

    速算技巧：WPL = 所有非叶子节点权值之和 = 8 + 15 + 20 + 35 - 35（根不算）= 8 + 15 + 20 + ... 等等，正确公式应该是 WPL = 所有非根的内部节点权值之和。 - 内部节点：8、15、20、35 - WPL = 8 + 15 + 20 + 35 - 35（减去根，因为根的路径长度为 0）= 不行 - 正确速算：WPL = 所有合并产生的中间节点权值之和（不包括根） = 8 + 15 + 20 = 43？也不对

    ⚠️ 直接套公式更稳：WPL = Σ(叶子权值 × 路径长度)，按层数手算最不易错。

    【例 5】系统可靠性（串并联，必考 1 题）

    题干：一个系统由 3 个子系统串联组成，子系统 A 由 2 个并联模块（各 0.9）、子系统 B 单模块（0.85）、子系统 C 由 3 个并联模块（各 0.8）。求系统整体可靠度。

    公式： - 并联：R = 1 - (1-R1)(1-R2)...(1-Rn) （全坏才坏） - 串联：R = R1 × R2 × ... × Rn （任一坏全坏）

    解： 1. 子系统 A（2 个并联）：R_A = 1 - (1-0.9)² = 1 - 0.01 = 0.99 2. 子系统 B：R_B = 0.85 3. 子系统 C（3 个并联）：R_C = 1 - (1-0.8)³ = 1 - 0.008 = 0.992 4. 整体（串联）：R = R_A × R_B × R_C = 0.99 × 0.85 × 0.992 ≈ 0.835

    易错点：先算每个子系统的并联可靠度，再串联相乘；不要颠倒先后。

    【例 6】海明码校验位数（必考 1 题）

    题干：要传输 8 位信息码，需要多少位海明校验位？校验位插在哪些位置？

    公式：信息位 n，校验位 k 满足 2^k ≥ n + k + 1，k 取最小满足值。

    解： 1. 试 k = 3：2³ = 8 < 8 + 3 + 1 = 12 ✗ 2. 试 k = 4：2⁴ = 16 ≥ 8 + 4 + 1 = 13 ✓ 3. k = 4（最小值）

    校验位插入位置（从 1 开始编号，2 的幂次位置为校验位）： - 位置 1 = 校验位 C1（2⁰） - 位置 2 = 校验位 C2（2¹） - 位置 3 = 数据位 D1 - 位置 4 = 校验位 C4（2²） - 位置 5-7 = 数据位 D2, D3, D4 - 位置 8 = 校验位 C8（2³） - 位置 9-12 = 数据位 D5, D6, D7, D8 - 总长度 = 12 位

    速记口诀：信息位 8 → 校验 4 位、信息 16 → 校验 5 位、信息 32 → 校验 6 位。

    【例 7】PV 操作（生产者-消费者基础题）

    题干：缓冲池有 N 个位置，1 个生产者、1 个消费者。请用信号量实现同步互斥。

    解（三个信号量必备）： ``` 信号量定义： - mutex = 1 // 互斥访问缓冲区 - empty = N // 空位数（资源信号量） - full = 0 // 满位数（资源信号量）

    生产者 Producer： while(true) { 生产一个产品 item; P(empty); // 申请空位（资源 P） P(mutex); // 申请互斥锁（互斥 P） 把 item 放入缓冲区; // 临界区 V(mutex); // 释放互斥锁（互斥 V） V(full); // 通知有满位（资源 V） }

    消费者 Consumer： while(true) { P(full); // 申请满位 P(mutex); // 申请互斥锁 从缓冲区取一个 item; V(mutex); // 释放互斥锁 V(empty); // 通知有空位 消费 item; } ```

    核心口诀："资源 P → 互斥 P → 临界区 → 互斥 V → 资源 V"——顺序不能颠倒，否则可能死锁！

    死锁分析：若把 P(mutex) 和 P(empty) 顺序颠倒： - 生产者先获得 mutex，再 P(empty) 发现没空位被阻塞 → 抱着锁睡 - 消费者要释放 V(empty) 需要先 P(mutex) → 拿不到锁 - → 死锁

    嵌入式系统软件层次： 应用软件层 ← 业务应用 ───────────── 中间件层 ← 通信、消息、数据库中间件 ───────────── RTOS 内核 ← 任务调度、内存、同步通信 ───────────── BSP 板级支持包 ← 设备驱动、HAL 硬件抽象 ───────────── 硬件层 ← CPU + 存储 + I/O 外设

    RM 可调度判据例题：

    例：3 个周期任务 T1(C=20,T=100), T2(C=30,T=150), T3(C=80,T=300)，能否用 RM 调度？

    • 利用率 U = 20/100 + 30/150 + 80/300 = 0.2 + 0.2 + 0.267 = 0.667
    • RM 判据：U ≤ 3×(2^(⅓)-1) = 0.779
    • 结论：0.667 < 0.779 ∴ 可调度

    优先级反转例题：

    任务 H（高）、M（中）、L（低）共享资源 R： 1. L 先锁 R 运行； 2. H 抢占 L，请求 R 被阻塞； 3. M 抢占 L 运行（与 R 无关）； 4. H 被 M 间接阻塞（优先级反转发生）

    解决方案： - 优先级继承协议（PIP）：L 临时继承 H 的优先级 → M 无法抢占 L → L 尽快释放 R - 优先级天花板协议（PCP）：L 一锁 R 就提升到该资源的最高优先级（天花板）

    21.7 架构方法论补强（ABSD / AOP / MDA / CBSD）¶

    ABSD（基于体系结构的软件设计）6 步骤：

    步骤 任务 输出
    1. 架构需求 标识构件、获取需求 需求规格、ASR
    2. 架构设计 提出方案、迭代 架构图、设计说明
    3. 架构文档化 编写架构说明书 + 测试规格 文档
    4. 架构复审 由专家评审 评审报告
    5. 架构实现 按架构构造系统 可运行系统
    6. 架构演化 适应需求变化 新版本架构

    核心特征：自顶向下、递归细化、视角与视图

    AOP（面向方面编程）5 大核心概念（2019 真题）：

    概念 英文 含义
    切面 Aspect 横切关注点的模块化（如日志、事务）
    连接点 Join Point 程序执行中可以插入切面的点
    切入点 Pointcut 匹配连接点的表达式
    通知 Advice 在连接点上执行的动作（前置/后置/环绕/异常/最终）
    织入 Weaving 将切面应用到目标对象并创建代理对象的过程；分编译时织入（AspectJ）和运行时织入（Spring AOP）

    ⚠️ 易错点：引入(Introduction) 是 Advice 的一种特殊形式（向已有类添加新方法/字段），不是 5 大核心概念之一。2019 真题考的就是上述 5 个标准概念，不要把"引入"当作核心概念答。

    AOP 应用场景：日志、事务、安全、缓存、监控（Spring AOP）

    MDA（模型驱动架构）三层模型：

    模型 全称 含义
    CIM 计算无关模型 业务模型，与计算实现无关
    PIM 平台无关模型 系统模型，与平台无关
    PSM 平台相关模型 针对具体平台的实现模型

    转换路径：CIM → PIM → PSM → 代码（自动生成）

    基于复用 vs CBSD（基于构件的开发）：

    维度 软件复用 CBSD
    复用对象 任意层次（代码/设计/需求） 标准构件
    复用方式 拷贝、参数化、继承 组装
    关键 复用库 构件规约、接口、组装机制

    构件组装的三种方式： - 黑盒组装：只通过接口，不修改构件 - 白盒组装：可见且可修改源码 - 灰盒组装：可见但仅修改部分（如扩展点）

    21.10 PKI 与 CBAM 计算补强¶

    X.509 数字证书核心字段： - 版本号、序列号、签名算法、颁发者(CA)、有效期、主体（持有者）、主体公钥、CA 数字签名

    CA 信任链验证流程： 1. 检查证书有效期 2. 验证 CA 签名（用上级 CA 公钥） 3. 检查证书撤销列表 CRL 或 OCSP 4. 检查主体身份匹配

    CBAM 计算示例：

    场景 A：投资 100 万改造缓存，预期年节省 300 万 → ROI = (300-100)/100 = 200% 场景 B：投资 200 万异地多活，预期年节省 500 万 → ROI = (500-200)/200 = 150% 决策：A 的 ROI 高，优先实施 A

    CBAM 步骤：场景整理 → 优先级 → 收益估算 → 成本估算 → ROI 计算 → 决策

    等保 2.0 五级差异（高频送分）：

    等级 名称 适用
    一级 用户自主保护 一般信息系统
    二级 系统审计保护 一般企业系统
    三级 安全标记保护 政府、金融、医疗等关键信息系统（最常考）
    四级 结构化保护 重要国家系统
    五级 访问验证保护 极端重要系统

    二十二、易混辨析矩阵（考前速扫）¶

    易混点 正确辨析
    ATAM vs SAAM SAAM偏场景可修改性分析；ATAM覆盖多质量属性并强调权衡
    SOA vs 微服务 SOA偏企业集成与集中治理；微服务偏独立部署与去中心化治理
    CAP vs BASE CAP是分布式约束；BASE是工程化取舍（基本可用、软状态、最终一致）
    工厂方法 vs 抽象工厂 工厂方法解决单一产品层次；抽象工厂生产一族相关产品
    适配器 vs 桥接 适配器用于兼容既有接口；桥接用于抽象与实现独立演化
    状态 vs 策略 状态强调状态驱动行为切换；策略强调算法可替换
    装饰器 vs 代理 装饰器增强职责；代理控制访问（远程、权限、延迟加载）
    数字签名 vs 数字信封 签名解决完整性与不可抵赖；信封解决机密传输
